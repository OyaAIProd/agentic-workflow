# Template Checkpoint

Format standardise pour les points de situation.

## Usage

Copier et adapter ce template lors des checkpoints :

```markdown
## Checkpoint

Fait :
- [element complete 1]
- [element complete 2]

En cours :
- [tache actuelle]

A faire :
- [prochaine etape 1]
- [prochaine etape 2]

Objectif global : [vision / but final du travail en cours]

Ajouts : [modifications, enrichissements, pivots decides en cours de route]
```

## Declencheurs

Produire un checkpoint :
- Apres livraison d'un fichier, module ou fonctionnalite
- Toutes les 3-5 reponses sur un travail continu
- Avant une decision architecturale ou un pivot
- Sur demande explicite de l'utilisateur
- Quand le contexte devient dense ou risque de se perdre

## Bonnes pratiques

- Rester concis : bullet points, pas de prose
- Etre factuel : pas d'intentions vagues
- Nommer precisement les fichiers/modules concernes
- Mentionner les blocages ou incertitudes dans "A faire"
- Pas d'emoji dans les checkpoints
